Quick start (60 seconds)

You need an AI coding assistant. No API keys, no database.

# 1. Create your own copy git clone https://github.com/jonyfs/llm-wiki-template my-wiki cd my-wiki # 2. Drop a source into raw/ cp ~/Downloads/article.md raw/ # 3. Ask your assistant to ingest it "Ingest raw/article.md into the wiki." # 4. Ask questions against the wiki "What does the wiki say about X?"

Works with Claude Code, Cursor, GitHub Copilot, OpenCode, and Codex. See README.md for the full walkthrough.

Frequently asked questions

Short answers to the questions people ask first.

Do I need an API key or database?

No. You need an AI coding assistant that reads markdown. Everything stays in plain files in git.

How is this different from RAG?

RAG rebuilds an answer from chunks every question. A wiki is compiled once and kept current, so cross-references and contradictions already exist.

Can I use my own sources?

Yes. Drop articles, papers, notes, or data into raw/ and ask the assistant to ingest them.

Does it work offline?

Yes. Files are local; the assistant reads them directly. No network calls required for the wiki itself.

Who maintains the wiki?

The assistant does, following the skills in .agents/skills/. You curate sources and ask questions.

The idea, in Karpathy's words

A short reading of the LLM Wiki gist, paraphrased for builders.

Most tools that work with documents use retrieval. You upload files, and at question time the model pulls the relevant pieces and writes an answer from them. That works, but the model starts over on every question. Nothing accumulates, and a subtle question that spans several documents means reassembling the same fragments again.

An LLM wiki works the other way. The model reads each source once and writes what it learned into a folder of linked markdown pages. It updates topic pages, revises summaries, flags where new material contradicts older claims, and keeps a running synthesis. Knowledge is compiled once and then kept current, instead of being rebuilt on every query.

The result is a persistent, compounding artifact: cross-references already exist, contradictions are already flagged, and each source you add or question you ask makes the notebook richer.

The three layers

The schema is the unusual part: instead of a generic RAG pipeline, you give the assistant a small set of rules (this template's AGENTS.md and .agents/skills/) and it becomes a disciplined maintainer of the wiki.

Concepts, explained simply

The vocabulary the template uses. Plain-language definitions, no jargon.

Source page

One page per raw file. Records what the source says, its role, and a claims ledger you can cite as [[slug]] C1.

Entity page

A person, org, product, or place that appears across sources. Collects everything the wiki knows about it.

Concept page

An idea, method, or theme. Explains it and links back to the sources that support it.

Synthesis page

A durable answer to a question that spanned several pages. Filed so the next question starts further ahead.

Wikilink

A bare [[slug]] link between pages. These links are what make the graph navigable, like in Obsidian.

Frontmatter

YAML at the top of every page: title, type, sources, dates. The schema the assistant validates against.

Ingest

Read a raw source once, write or update wiki pages, update the index and log. Knowledge compiled once.

Query

Answer from the wiki first. File the answer as a synthesis when it is reusable.

Lint

A health check: broken links, missing fields, stale claims, orphan pages.

Compounding

Each source and each question makes the notebook richer. Nothing is rebuilt from scratch.

The skills pipeline

Each operation is a skill the assistant follows. No improvisation, no skipped steps.

Ingest

Reads a raw source once, writes or updates source/entity/concept pages, updates index and log. Knowledge compiled once.

Query

Answers from the wiki first, cites pages inline. Files the answer as a synthesis when reusable.

Lint

Checks broken links, missing fields, stale claims, orphans. Keeps the notebook honest.

Refresh

Detects drift between raw files and source pages. Reports, never silently rewrites.

Common pitfalls

Things that trip people up the first time.

Empty wiki after ingest

Make sure the source is in raw/ and you asked the assistant to ingest it. The wiki is not auto-populated.

Broken wikilinks

Run the lint skill. It reports missing targets so you can fix or remove them.

Stale claims

Use refresh to detect drift between raw files and source pages.

Too many pages

That is fine. The index and search keep it navigable; compounding is the point.

An ingest, step by step

What actually happens when you say "ingest raw/article.md".

  1. Read the source once. The assistant reads raw/article.md end to end.
  2. Create a source page. Writes wiki/sources/article.md with frontmatter, summary, and a claims ledger.
  3. Touch related pages. Updates or creates entity and concept pages that the source mentions, adding wikilinks.
  4. Update the index. Adds entries to wiki/index.md under the right category.
  5. Append to the log. Records the operation in wiki/log.md with date and title.
  6. Done. The source is now part of the compiled knowledge base. Next question starts further ahead.
