    How it works

    You add sources. The assistant files them. You ask questions, and a wiki skill handles each step.

    1. raw/files, links and pasted textsaved here, never editedyou choose them
    2. LLM assistantloads a wiki skill firstthen reads, writes or answersskills in .agents/skills/
    3. wiki/sources · entities · conceptssyntheses · index · loggrows as you add

    Questions go to wiki/ first. The assistant opens the raw files only to check a detail.

    Give it almost anything

    Start with what you already have. You choose the sources, and the assistant never edits them.

    Files on your computer

    Notes, markdown, text, PDFs, images and data files such as CSV. Copy them into raw/ and ask the assistant to ingest them.

    Links from the web

    Paste a link and the assistant asks whether to save the page into raw/ first. If you say yes, it keeps a clean copy and notes the date it was fetched.

    Text you paste

    Paste an email, a chat thread or a transcript. The assistant asks before saving it as a file in raw/, then ingests it like any other source.

    Screenshots and scans

    Images count as sources too. The assistant separates what it can read in the image from what it is guessing, and says so when it can't read one reliably.

    Whatever the format, the assistant needs a tool that can read it. If it can't, it tells you instead of guessing.

    Every request goes through a skill

    When you ask the assistant to ingest, answer or remove something, AGENTS.md tells it to load the matching skill first. That is why every answer is built the same way: it starts from the index, uses your pages, cites them and logs any change it makes.

    You saySkillWhat happens
    Ingest this file or linkwiki-ingestReads the source, writes or updates the pages it affects, then updates the index and log. A link or pasted text is saved to raw/ first, and only after you say yes.
    What does the wiki say about X?wiki-queryStarts from the index, reads the relevant pages, opens raw files only to verify, and cites what it used. It can save a useful answer as a synthesis page.
    Just tell me, don't change anythingwikiThe same lookup, but it cannot write, create or delete a file.
    Check the wikiwiki-maintenanceLint looks for broken links, missing fields and orphan pages. Refresh reports raw files that changed after their page was written.
    Remove everything about Xwiki-deleteLists every mention, shows what would change and waits for your confirmation. It never touches raw files.
    Write or fix a pagewiki-writingSets the page type, headings, frontmatter and citation style before any wiki prose is written.
    Not sure what to askwiki-routerPicks exactly one of the skills above, or asks you one question.

    These are instructions the assistant follows, not a lock. The lint script checks the result.

    Shortcut commands, where your assistant supports them:

    /wiki-ingest/wiki-query/wiki/wiki-lint/wiki-refresh

    Examples from an ordinary week

    Made-up situations, but the steps are the real ones.

    Studying for an exam

    You keep lecture PDFs, your class notes and two articles you found online. You tell the assistant to ingest them, and the links are saved to raw/ after you approve it.

    Before the exam you ask: "What did the course say about Keynes, and where does the article disagree?" The answer cites the lecture page and the article page.

    Running a small business

    You drop in proposals, signed contracts, meeting notes and emails exported as text. Each one is ingested the same way.

    Months later: "What did I promise this client about delivery, and did the scope change?" The assistant points to the proposal and to the later email, and says where they differ.

    Planning a trip

    You save a few blog posts as links, the booking confirmation as a PDF and screenshots of the map.

    You ask: "We land on Sunday night and the museum closes on Mondays. Which day works?" The answer comes from your saved sources, and each claim links to the page it came from.

    Keeping a team's decisions

    You add meeting notes, design docs and issue threads over a few months.

    A new teammate asks: "Why did we pick Postgres?" The assistant answers from the decision pages and can save the answer as a synthesis page, so the next person finds it already written.

    In each case, wiki-query handles the questions and wiki-ingest handles every source you add.

    What it does for you

    Plain files, a few scripts and instructions your assistant follows. Nothing runs in the background.

    Answers you can check

    Claims in wiki pages carry a footnote that points at the raw file. When the assistant answers, it names the pages it used, so you can open them.

    Your sources stay untouched

    The assistant reads raw/ but never edits it. Everything it writes goes into wiki/, and git keeps the history.

    A record of every change

    wiki/index.md lists every page. wiki/log.md records what the assistant did and when.

    Good answers get reused

    A useful answer can be saved as a synthesis page. The next similar question starts from that page instead of the raw files.

    Problems show up early

    Lint catches broken links and missing fields. Refresh tells you when a raw file changed after its page was written.

    Removing things is safe

    Removing a subject lists every mention first and waits for your yes. The raw files stay where they are.

    Who this is for

    If one of these sounds like you, it's worth an afternoon.

    Readers and researchers

    You save more papers and articles than you can keep in your head, and want to ask questions across them.

    Builders and founders

    You keep notes on competitors, customer calls and past decisions, and can never find the one you need.

    Students and writers

    You want to start writing with the citations and cross-references already lined up.

    Teams

    You want one shared notebook in git that stays up to date without someone owning it full time.

    Skip it if you need search over millions of documents or a hosted service. This is a folder of markdown on your own machine.

    Quick start

    You need an AI coding assistant that can read your files. No API keys, no database.

    # 1. Create your own copy git clone https://github.com/jonyfs/llm-wiki-template my-wiki cd my-wiki # 2. Add sources: copy files into raw/ cp ~/Downloads/lecture.pdf raw/ # 3. Ask your assistant to ingest them (it loads wiki-ingest) "Ingest raw/lecture.pdf into the wiki." "Save https://example.com/article into raw/ and ingest it." # 4. Ask questions (it loads wiki-query) "What does the wiki say about X?"

    Common questions

    Do I need an API key or database?

    No. The wiki is plain markdown files in git. You only need an AI coding assistant that can read and write them.

    How is this different from RAG?

    RAG finds the relevant chunks and writes a fresh answer every time you ask. Here the assistant writes the pages ahead of time, so links between ideas and conflicting claims are already on the page when you ask.

    What can I add to it?

    Files you copy into raw/: notes, markdown, PDFs, images and data files. Links and pasted text work too, once you agree to save them there. The assistant still needs a tool that can read the format.

    Do I have to use the skills?

    They are how the template works. AGENTS.md tells the assistant to load the matching skill before it ingests, answers or removes anything. It's an instruction, not a lock, so if an answer looks like it skipped the wiki, ask it to use the wiki skill and cite its pages.

    Does it work offline?

    The files do. The wiki is local and needs no server. Whether the assistant works offline depends on which assistant you use.

    Who maintains the wiki?

    The assistant does, following the instructions in .agents/skills/. You choose the sources and ask the questions.

    Where the idea comes from

    Andrej Karpathy described the pattern in a gist. This is a short paraphrase, not a quote.

    Most document tools use retrieval. You upload files, and when you ask something the model pulls out the relevant pieces and writes an answer. It works, but every question starts from zero. Nothing builds up, and a question that spans several documents makes the model piece the same fragments together again.

    In an LLM wiki, the model reads each source once and writes what it learned into a folder of linked markdown pages. When new material arrives it updates the topic pages, revises summaries, and points out where something contradicts an older claim.

    What you end up with is a set of pages you can open, read and correct yourself. The links between ideas are already there, and each source you add gives the next question more to draw on.

    Three layers

    1. raw/read-only sourcesthe assistant never edits these
    2. wiki/pages the assistant writessources, entities, concepts, syntheses
    3. schemaAGENTS.md + skillsthe instructions it follows

    Instead of a generic pipeline, the assistant gets a short set of instructions (AGENTS.md and .agents/skills/) in this template, and it follows them.

    The vocabulary

    Source page

    One page per raw file. It summarizes what the source says and numbers its claims so other pages can cite them, like [[slug]] C1.

    Entity page

    A person, company, product or place that shows up in more than one source. Gathers what the wiki knows about it in one spot.

    Concept page

    An idea, method or theme. It explains the thing and links to the sources behind it.

    Synthesis page

    The saved answer to a question that needed several pages. Next time, you start from it.

    Wikilink

    Links like [[slug]] take you from one page to another. They are what the graph above draws, and Obsidian reads them too.

    Frontmatter

    A small block of YAML at the top of each page with title, type, sources and dates. The lint script checks it.

    Ingest

    The assistant reads a raw source, writes or updates the wiki pages it touches, and records it in the index and log.

    Query

    Ask a question. The assistant answers from the wiki first and can save a useful answer as a synthesis page.

    Lint

    A health check for broken links, missing fields, stale claims and pages nothing links to.

    Skill

    A markdown file in .agents/skills/ that tells the assistant how to do one job, such as ingest, query or lint.

    When something looks wrong

    Empty wiki after ingest

    Check that the file is in raw/ and that you actually asked the assistant to ingest it. Nothing fills the wiki by itself.

    Broken wikilinks

    Run the lint skill. It lists links that point nowhere so you can fix or remove them.

    Stale claims

    Run refresh. It shows which raw files changed since their source pages were written.

    Too many pages

    That's normal. Use wiki/index.md and the search script to find your way around.

    The answer ignored the wiki

    Ask the assistant to use the wiki skill and cite the pages it read. If the pages are not there yet, ingest the source first.

    An ingest, step by step

    What happens when you tell the assistant to ingest raw/article.md.

    1. It loads the skill wiki-ingest and reads wiki/index.md.
    2. The assistant reads raw/article.md from start to finish.
    3. It creates wiki/sources/article.md with frontmatter, a summary and a numbered list of claims.
    4. It edits or creates the entity and concept pages the source mentions, and links them.
    5. It adds the new pages to wiki/index.md, under the right heading.
    6. It adds an entry to wiki/log.md with the date and a title.
    7. The source is now part of the wiki, so your next question can use it.
